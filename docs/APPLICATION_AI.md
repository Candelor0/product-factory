# 开发预算与项目文本 AI 协议

日期：2026-10-04。对应 D-032、FR-002/009 与 S4-03 的预算及项目授权子项。本文描述当前源码实现；任务状态和验证结论以 [TASKS.md](TASKS.md) 及其关联证据为准。

## 两套独立账本

| 账本 | 覆盖请求 | 限额与持久记录 |
| --- | --- | --- |
| 开发累计账 | 工作台连接检查、需求/方案生成、源码生成与修复等模型请求 | `provider.json` schema 2；累计调用上限 1–10000，可选累计 token 上限 1–100000000，`null` 表示不启用 token 限额 |
| 项目应用账 | 已授权本地应用提交的文本 AI 请求 | `projects/<projectId>/runs/app-ai.json` schema 1；每项目累计调用上限 1–1000、累计 token 上限 1–100000000，两项均必填 |

应用请求使用项目账本的预留和结算回调，不再计入开发账。项目账不按授权批次或窗口重新计算；修改额度、重新授权、撤销、重启、源码回退均不清空已有调用和用量。开发账是全局累计账，本轮没有按开发项目拆账。

两套调用共用主进程的一个模型请求槽。繁忙、预先取消、缺少密钥等检查在预留之前完成，被拒绝的请求不会发送；不排队自动重试。

## 授权范围

用户在工作台填写明确用途并授予项目额度。用途最多 500 个 UTF-8 字节，授权保存当前确认计划的 `planRunId`、`planInputHash`、`planArtifactHash`，以及模型连接的 `id/provider/baseUrl/model`。授权提交必须匹配读取时的账本 `expectedRevision` 与当前 `connectionId`。

修改供应商、地址、模型、提交新 Key 或删除 Key 会改变连接 ID；仅修改额度不会改变。计划或连接不匹配时，原授权变为失效，需用户核对后重新授权。重新授权不会把原用量转为零。归档项目不能继续调用。

只有「打开本地应用」建立的持久会话可请求应用 AI。普通预览、启动检查、自动修复检查中的临时会话均拒绝调用；临时会话不会因项目已有授权而获得权限。项目和构建来源由可信宿主绑定，生成页面不能在请求中指定其他项目、用途、模型、Key 或额度。

用途随请求发送给模型，但不是能识别所有语义越权的分类器。授权后的应用代码可以发起收费请求；生成规范要求由明确用户动作触发，当前宿主不把页面点击手势作为逐次授权凭证。额度是持续授权的执行边界。

## SDK 与单次文本调用

```ts
import { appAi } from '@factory/ai';

// 每次新的用户操作生成一个 ID；结果不确定时保留原 ID 和原文本。
const request = {
  requestId: crypto.randomUUID(),
  text: '请将这段由用户选择的文字整理为摘要。',
};
const answer = await appAi.generateText(request);
```

也可直接导入 `generateText`。`requestId` 必须为规范的小写 UUID v4；`text` 非空且最多 16000 个 UTF-8 字节。SDK 向当前隔离会话的 `POST /app-ai` 发送 `{ schemaVersion: 1, requestId, text }`，不携带浏览器凭据；宿主拒绝请求中的未知字段。整个请求体最多 32 KiB；宿主另有每会话一分钟 30 次入口请求限制及单请求互斥。它们不替代持久预算。

主进程发送一次非流式文本请求，固定纯文本 system、固定 `max_tokens: 1024`，不提供工具、不要求 JSON 输出、不执行模型返回代码。只有一个完整 assistant 文本结果才可返回，正文最多 64 KiB；截断、工具调用、无效结构或已配置 Key 的回显会被拒绝。授权用途与本次文本是提交给供应商的输入，服务不会自行读取业务数据库补充上下文。

服务响应为 `{ ok: true, value: { text } }` 或 `{ ok: false, error: { code, message } }`。SDK 成功返回字符串，失败抛出带 `.code` 的 `Error`；不隐式重试。网络和无效响应分别可能表现为 `APP_AI_NETWORK`、`APP_AI_RESPONSE`，两者都不能证明供应商未收到请求。

## 预留、结算与未知用量

预留数量按最终供应商请求 JSON 的 UTF-8 字节数计算：

```text
reservedTokens = requestBodyBytes + max_tokens + 1024
```

这是一项保守的本地占用规则，不是 tokenizer 结果、供应商实际 token 或单次费用上限。请求先原子保存一次调用及未知用量的预留，再发送网络请求；剩余额度不足则停止。收到合法的非负安全整数 `prompt_tokens/completion_tokens` 后，已知用量替换本次预留。实际用量超过预留时仍照实记账，阻止随后超额请求。

无 usage、无效 usage、网络失败、超时、取消或崩溃留下的未结算请求持续占用预留，重启不会退款。若已收到有效 usage，随后正文解析或敏感内容检查失败，仍保留已结算的已知用量。页面拿到错误不等于调用免费。

普通未知调用会占用额度，直到剩余额度不足而停止新请求；不会仅因一次未知就无条件封禁全部剩余额度。累计用量无法以安全整数表示时，开发预算或项目未结算预留持久化为 `Number.MAX_SAFE_INTEGER`，保留先前精确计数和未知标记，不编造累计 token。所有受支持的有限 token 上限都无法继续放行；重启或上调到最大额度也不会解除这一状态。开发账主动使用 `maxTokens: null` 时仍按调用次数限额执行。

开发预算不足返回 `TOKEN_BUDGET_EXCEEDED`，调用次数不足返回 `BUDGET_EXCEEDED`；项目额度或记录容量不足返回 `APP_AI_LIMIT`。预算占用与供应商已知 token 分开显示。本轮没有价格配置，不据此显示虚假的精确金额。

## 请求意图与去重

项目回执保存 `requestId`、请求哈希、预留数量及可空的输入/输出 token。哈希覆盖原文本、授权用途、计划绑定与连接 ID，不保存文本正文或模型回复。

- 同 ID、同请求已登记：返回 `APP_AI_REQUEST_RECORDED`，不再调用供应商、不再次收费；由于不缓存回复，不能返回原答案。
- 同 ID、不同请求：返回 `APP_AI_REQUEST_CONFLICT`，不覆盖原记录。
- 尚无回执：重新检查授权、连接、账本和额度后，先登记意图再发送。一次仍未登记的失败不能被解释为已成功调用。

权限检查先于去重，失效或撤销的会话不能借旧 ID 绕过权限。崩溃后的未结算意图不自动重放，也不因为没有答案就自动改成成功或免费。新的 ID 表示新的可能收费操作，不能用更换 ID 隐藏一次不确定请求。

每项目最多 1000 条回执，完整账本最多 1 MiB。记录不淘汰，到限拒绝新增；没有通过清理旧回执重复收费的路径。当前无人工消账、未知用量核销、账本恢复或容量轮换 UI。

## 原子保存与删除检测

项目账本和 `runs/app-ai.initialized.json` 分离。首次更新先创建并同步空 revision 0 账本，再创建并同步初始化标记，随后提交授权或请求变更。空账本存在但标记尚未创建的初始化中断可继续完成；非空账本缺少标记拒绝使用。标记存在但账本缺失同样拒绝重建，返回 `APP_AI_MISSING`。

更新克隆当前记录，校验完整 schema、项目归属和容量，整体 revision 加一。独占临时文件写入并 fsync 后，重查旧记录哈希及临时内容，原子 rename 发布；非 Windows 另同步父目录。文件必须是普通文件，拒绝符号链接、硬链接、损坏格式、未知 schema 和错误项目记录。已有内容变化时拒绝覆盖。

项目账本发布后出现异常返回 `APP_AI_COMMIT_UNCERTAIN`，即使文件可能已经保存也不据异常自动发模型请求。重新读取若发现意图，按已登记处理。发布前失败保留旧记录。开发账使用独立的字节哈希比较及发布后精确回读；无法确认或结算写入失败时，当前服务停止后续调用，不把内存退款当成持久结算。

若外部同时删除项目账本与初始化标记，新进程无法把该状态与从未初始化区分。这不是防本机管理员篡改的审计系统，也不承诺多写者数据库事务或完整系统沙箱。源码检查点只恢复源码，不回退业务 JSON、授权账本或已登记的 AI 用量。

## 旧版迁移、取消与隐私

开发配置从旧 schema 1 原子迁移到 schema 2，保留密钥密文和原调用/用量，已知 token 形成初始预算，旧未知调用保存在 `legacyUnknownUsageCalls`。旧未知没有可恢复的预留估计，因此拒绝启用非空 token 限额，返回 `TOKEN_USAGE_UNKNOWN`；原有调用次数限额仍可用。不会把旧未知当作零或通过升级清账。项目应用账本使用新的 schema 1，与开发配置版本号无关。开发配置升级后应继续使用 0.13.0 或更新版，旧版不能读取 schema 2。

撤销项目授权、关闭或替换应用窗口、归档和确认方向失效会取消所属请求。会话仅持有自己的 AbortController，不会因关闭另一个窗口而随意取消其他项目请求。取消后即使供应商忽略 abort 并晚到返回，正文和晚到结算也不会进入已撤销会话；发送过的请求仍可能计费，已持久化预留保留。

Key 仅由可信主进程使用，生成页面没有配置或凭据读取入口。授权用途会保存在项目授权记录中，文本输入与输出不写 AI 账本。请求前及返回时的有限凭据扫描不能保证识别所有私人信息；应用仍需由用户选择要发送的文本，也可能自行保存所获答案到业务数据。

源码导出包含固定 AI SDK 与协议依赖，不包含项目授权、用量回执、业务数据或宿主 Key；导出的源码不因此获得外部服务权限。维护者仍需提供受控协议宿主。本轮不提供任意模型代理、工具执行、独立 AI 后端或自动迁移服务。
