# 已有应用的自然语言修改协议

日期：2026-10-05。对应[D-038](DECISIONS.md#2026-10-05自然语言修改已有应用)、[D-039修复上下文补充](DECISIONS.md#2026-10-05核心主流程局部实测)、FR-008/FR-012及S4-02。本文描述截至0.19.0的源码协议和边界；任务状态与实际验证结论以[TASKS](TASKS.md)及关联证据为准。

## 入口与适用范围

在已确认需求、页面方向和当前开发计划下，用户可对已有源码提交一条页面或行为调整要求，点击“修改并检查”。流程复用[自动开发编排](AUTOMATIC_WORKFLOW.md)：修改源码、受控构建、隔离启动观察，必要时进行至多一次有限修复。

新修改必须基于非空源码，且最新源码检查点属于当前确认计划。提交时记录的源码revision过期、计划失效、项目归档或可信工具链不可用时，不开始新的执行。修改请求本身不会更新需求、页面确认、开发计划或用户核验记录。

当前入口面向已确认范围内的调整。主要目标、页面、权限或数据用途改变时，应先在工作台重新确认受影响的需求和页面方向。提示词要求模型遵守这一边界，但系统没有通用的自然语言范围判定器，不能仅靠模型回复证明范围或业务正确性。

## 修改文字与隐私

修改要求不能为空，最多2000个JavaScript字符串长度单位、8000个UTF-8字节；部分emoji占两个长度单位。主进程先校验原输入长度、控制字符和Unicode有效性，再去除首尾空白；规范化后的文字参与请求去重。换行和制表符允许，未配对代理字符与被禁止的控制字符拒绝。

提交的修改要求会以可读文本保存在本项目的流程记录中，并随本次请求发送给用户配置的模型供应商。它不是API Key那样的系统加密凭据。界面在提交处说明这一点；用户不应把密钥、密码或个人业务正文写入要求。

正式应用在保存新父请求之前，用模型服务扫描已配置密钥及常见凭据模式；内部修改执行器在保存子意图之前再次校验。发现疑似凭据时拒绝本次新请求，不将该输入写进执行记录或发给模型。扫描包括部分常见编码形式，但不保证识别所有私人内容、秘密或编码，不能作为完整隐私过滤器。

后续编译或启动修复也会收到同一修改要求。保存新的修复意图之前，修复执行器核对修改前源码检查点、哈希及当前确认计划，并再次扫描要求；文字仍只保存在父流程记录中。修复子记录保存完整请求的哈希和执行元数据，不另存要求正文或模型对话。

模型收到当前确认计划、允许读取的源码和明确修改要求。修改流程不会读取或发送`data/generated`中的真实业务值。源码本身若包含私人内容，仍可能成为模型上下文；不得据此承诺所有项目内容都留在本机。

流程记录保留明确用户要求，不保存完整模型对话、系统提示词、模型回复、工具参数或业务值；源码事务继续由源码存储保存。未提交的输入草稿及不确定请求暂存在工作台内存中，切换项目可保留，重新加载或退出不保证恢复。源码导出和业务JSON备份不会主动读取流程日志；若用户把私人内容写进源码，仍按各自导出规则处理。

## 请求与版本绑定

`runWorkflow`接受以下新请求。ID使用规范小写UUID v4，revision为非负安全整数；拒绝缺失或额外字段。

```ts
{
  schemaVersion: 2,
  requestId,
  projectId,
  planRunId,
  sourceRevision,
  mode: 'modify',
  instruction
}
```

原`schemaVersion: 1`的`generate`和`check`保持原字段、顺序与规范哈希。独立`generateSource`入口仍只接受旧版生成请求；不能通过该入口绕过父流程提交修改要求。

可信主进程读取并保存初始源码完整快照哈希，以及确认计划的ID、输入哈希和产物哈希。修改子请求还绑定相同源码revision、快照哈希和规范化要求；父流程用固定子请求ID查证对应记录，不能借用另一操作的最新结果。

相同父ID、相同规范请求只核对既有记录，不重发模型调用；同ID不同文字或其他参数返回`WORKFLOW_CONFLICT`。用户主动发起另一项修改时使用新ID；发生响应不确定时应核对原请求，不通过换ID重发来猜测结果。

0.19.0的新修改流程若需要编译或启动修复，会先在父流程的repair阶段保存`repairRequestVersion: 2`，再构造内部修复v2请求。请求包含当前待修源码revision，以及`modification`中的父workflowId、修改前sourceRevision/sourceHash和原instruction；启动修复还绑定实际runtimeReportId。模型同时收到当前确认计划、原修改要求和真实诊断，提示词要求保留本次要求，不以撤回修改或恢复旧页面消除错误。这是上下文与权限约束，不能证明模型必然保留了全部业务行为。

父流程在采用修复结果和读取历史时，根据阶段标记重建同一规范子请求，核对requestHash、计划、起始源码和结果身份。0.18.0已有的modify流程若repair阶段没有该标记，仍按原v1请求字段顺序和哈希核对，不补写标记或重发调用。工作台独立`repairSource`入口继续只接收v1，不能提交内部`modification`上下文；该入口也不会自动猜测并继承某次历史修改要求。

## 源码修改与数据边界

模型仍只有`list_files`、`read_file`和`apply_changes`三个受限工具。修改或删除已有文件前，必须读取该文件当前内容及哈希；批量请求夹带未读文件时，整批拒绝。自己修改过的文件再次修改前也需重新读取。新文件使用当前revision与`expectedHash: null`，每批仍最多32项。

每次模型等待后和工具执行前重新核对确认绑定与预期源码。只有当前子任务可核对的成功工具回执及源码检查点才能推进预期版本；外部改动、源码恢复或无法归属的事务不会被当成本次修改。相同内容重写可能产生新revision，但没有文件内容净变化时，源码阶段记录为`no_changes`，不能宣称已完成用户修改。

源码在既有事务边界逐次提交，已经提交的改动和检查点保留；整个多轮修改不是一个可以整体撤销的数据库事务。源码恢复只恢复源码，不回退业务数据、AI用量或授权。

构建和启动检查使用独立临时数据，不自动打开持久应用，不自动执行数据迁移。真实业务数据仍按[持久数据协议](PERSISTENT_APP_DATA.md)保存；结构变化需走[数据迁移](DATA_MIGRATION.md)的独立预览和明确确认。已打开的持久应用与用户主动数据操作不属于本轮源码事务，不承诺在修改期间冻结或回滚这些写入。

## 时限、预算与取消

| 范围 | 上限 |
| --- | --- |
| 修改源码阶段 | 4轮模型尝试、12次工具调用 |
| 后续有限修复 | 至多一次；4轮模型尝试、12次工具、5次构建、180秒 |
| 整个父流程 | 300秒；最多8轮模型尝试、24次工具、6次构建 |

4轮/12工具是修改源码子阶段的额度，不能误写成包含修复的父总额度。0.19.0补传修改要求不增加轮数、工具、构建或时间额度。编译修复后若启动又失败，不再获得第二次修复额度。每次模型调用仍受开发调用/token累计预算约束，未知用量、取消与未确认结果不按零计费；详见[应用AI与预算](APPLICATION_AI.md)。

取消锁住父流程并传递到正在执行的生成、修复、构建及启动检查，迟到响应不得继续写源码或调度后续阶段。已提交源码保留。重开后没有活动执行者的流程标为中断，不自动续费或继续工具操作；用户可检查已有源码，或明确提交另一项修改。

## 记录、历史与文件差异

`runs/workflows.json`继续作为唯一父流程台账，最多50条、2 MiB，不自动淘汰旧请求。首次保存修改请求将旧文件原子升级为schema 2；0.19.0首次保存带`repairRequestVersion: 2`的新修改修复阶段时，再将整个文件原子升级为schema 3。外层schema与请求版本不同：schema 3仍可包含原v1/v2请求和旧修复阶段。新程序读取schema 1/2/3，写入只升级、不降级；schema 1/2不能夹带新修复标记，未知未来格式拒绝读取。schema 3应使用0.19.0或更新版本，旧程序不能继续访问该记录。初始化标记`workflows.initialized.json`仍使用schema 1并保留相同storeId。

写入沿用独占临时文件、fsync、提交前内容复核、原子rename和精确读回。文件损坏、未来格式、身份不符、软硬链接和超限拒绝覆盖；标记存在而流程文件缺失时拒绝重新初始化。完整初始记录缺标记可补齐；两文件同时被外部删除仍无法识别。标记link/unlink之间中断会安全拒绝多硬链接，需保留现场处理，详见[自动开发协议](AUTOMATIC_WORKFLOW.md)。

界面列出最近20条开发与修改记录，可按原请求ID查看要求、来源与结果。文件差异以本次初始和已核定结果的精确检查点及快照哈希为依据，按文件路径和内容哈希计算新增、修改、删除；不是代码行差异，也不是模型生成的总结。查看历史不会拿最新源码替代历史结果。

仍在执行、取消、中断或阶段结果不能核对时，文件差异显示不可确认，不能解释为零改动。可核对的空差异只表示两端源码内容相同；不代表用户提出的业务要求已实现。技术状态“候选通过启动检查”同样不等于业务通过，应结合[需求差距报告](GAP_REPORT.md)重新核验；旧源码或构建上的用户结论不能自动沿用。

## 当前不支持

本增量不提供完整多轮聊天历史、任意现有仓库接管、任意依赖安装或宿主命令、自动更新确认范围、自动业务交互验收、自动迁移真实数据或自动打开持久应用。文件净差异无法证明无关功能没有回归，也不替代业务检查。当前发布范围按[D-037](DECISIONS.md#2026-10-05-d-037-mac先行windows延后)优先Mac；Windows延后，Mac干净安装和真实案例验收仍须单独完成。
