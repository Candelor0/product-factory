# 自动开发流程（D-036）

初版0.17.0，现行协议补充至0.19.0，对应FR-006、S3-02及AC-007/008/011/012/014。本协议说明已实现的控制边界；初版实际验证结果见[报告](evidence/2026-10-05/S3-02/workflow/result.md)，后续局部验证见[验收记录](ACCEPTANCE.md)，完整阶段状态只以[TASKS](TASKS.md)为准。

0.18.0由D-038扩展[自然语言修改](APPLICATION_MODIFICATION.md)，复用同一父流程及总限额。以下v1生成/检查语义保持，新增v2修改文字及schema升级另见该协议。

0.19.0补齐修改后修复的上下文：编译和启动修复均收到原用户要求、父流程ID及修改前源码revision/hash。提示词要求在保留当前确认范围和本次要求的前提下修复，不能以撤回修改换取无错误。技术检查仍不证明修改要求或业务已通过，修复预算没有增加。

## 用户流程

确认需求和页面方向，整理当前开发计划后，点击“自动开发”。工作台依次生成源码、受控编译、隔离启动检查，遇到可修复的编译或启动问题时进行至多一次有限修复。阶段结果、停止原因和实际尝试次数可查看，原有逐步操作仍保留。

“候选已通过启动检查”表示本次受测构建在有限观察期内没有固定类别的启动错误。它不表示页面交互、持久业务数据或全部需求已经通过；需打开候选并结合[差距报告](GAP_REPORT.md)逐项核验。流程不自动填写用户核验、不自动打开持久应用、不迁移或读取真实业务数据。

## 有界执行

| 项目 | 单次流程上限 |
| --- | --- |
| 生成阶段 | 1次，4轮模型尝试、12个工具调用 |
| 修复阶段 | 至多1次，4轮模型尝试、12个工具、5次构建、180秒 |
| 总体 | 300秒、最多8轮模型尝试、24个工具、6次构建 |

总体构建上限由一次初始构建和修复内部至多5次构建组成。编译修复成功后若启动仍报错，流程停止，不再开启第二个修复额度。模型服务在每次请求前独立核对调用/token预算，未知用量不会按零处理。模型“尝试”包含被预算拒绝的尝试，不等于实际计费请求数。

取消先锁住父流程，再传递到生成、修复、构建和启动检查；迟到供应商响应不能继续写源码或推进下个阶段。已经提交的源码保留，不通过取消回退检查点。达到时限、预算、不可修复错误、版本变化或持久化失败时停止。

## 记录与身份核验

`runs/workflows.json`独立保存父流程，最多50条、2 MiB，单条至多4阶段。严格解析字段、版本、时间、顺序和状态转换；父请求身份、计划绑定及已结束阶段不可变。文件原子写入、保留初始化标记，损坏或缺失不自动清空。内部storeId与workflows.initialized.json关联：完整初始记录先发布，再独占发布标记；仅标记缺失可从有效原记录补齐，标记存在而记录缺失则拒绝重建。

两文件同时被外部删除仍无法识别；标记发布的link/unlink窄窗口中断会因多硬链接拒绝访问，需要保留现场后恢复。目录限制仍不是抵御同用户任意磁盘修改的系统沙箱。

每个阶段执行前先保存意图及确定性子请求ID，完成后单独保存真实结果，再追加下一阶段。v1记录仅含ID、revision、哈希、时间和受信错误码。0.18.0的v2修改请求另保存用户明确提交的有界修改文字；不保存完整模型上下文、源码正文、模型回复、业务数据或密钥。已有生成/修复/构建/运行记录继续各自保存。

新修改修复阶段先保存不可变的`repairRequestVersion: 2`，首次写入该标记时将workflows外层schema原子升级为3。schema 1/2继续可读，旧未标记阶段仍按原v1子请求核对，不能自动补标记或改变历史哈希；后续写入不降级。内部修复v2将原要求纳入requestHash，修复子台账仍只存哈希和元数据，不增加文字副本。独立`repairSource`入口保持v1，不能由renderer指定内部修改上下文。各层版本、迁移和隐私细节见[修改协议](APPLICATION_MODIFICATION.md)。

协调器只读取对应子请求的真实记录，核对完整规范请求哈希、确认计划、源码版本及内容、构建和运行报告身份，不借用其他操作的最新结果。修复请求由父阶段标记决定使用v1还是v2；同一个子ID也不能掩盖要求、原源码或启动报告的差异。生成及修复新增源码必须能追溯到该子任务工具回执；外部写入或源码恢复不能被冒认为本轮修改。重开读取当前就绪候选时再次核验精确构建和启动报告，缺失或矛盾不继续显示当前候选就绪。

## 重复请求与中断

相同父请求重放只返回原记录；同ID不同内容拒绝。界面遇到响应不确定时，“核对原请求”仅按该ID只读查询，未知ID返回无记录，不会发起生成。刷新默认显示最新流程，指定ID读取不会借用更新的另一条流程。

重开将没有活动执行者的running父流程和未结束阶段标为interrupted，保留最后已记录的源码身份；不猜测是否收到供应商回复、不自动续费或执行下一阶段。若子任务已写入源码而父尚未记下，当前状态将显示版本已变化，源码仍由检查点/恢复服务核对。

用户可以明确点击“检查已有源码并继续”：建立新流程，跳过生成，重新编译和启动检查，必要时至多一次有限修复。这要求现有源码属于当前确认计划。再生成也是独立明确动作。工作台重载后的后台读取不等于新执行授权。

## 尚未覆盖

本增量没有自动业务交互测试、完整Blueprint分析worker、任意后端/依赖安装、自动数据迁移或全流程真实模型验收。D-038已增加明确的单次自然语言修改，跨轮对话澄清仍待完善。当前优先Mac干净环境与核心功能，Windows按D-037延后。固定编译与启动检查继承[受控构建](CONTROLLED_BUILD.md)、[有限修复](BOUNDED_REPAIR.md)和[运行反馈](RUNTIME_FEEDBACK.md)的边界。
