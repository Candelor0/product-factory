# 有限构建修复

日期：2026-10-04。D-027对应S3-02/AC-008的构建错误子项；D-029扩展的运行检查见[运行反馈协议](RUNTIME_FEEDBACK.md)。

## 用户操作

免费本地「构建并预览」保持独立。构建失败后可点击「自动修复并构建」，界面明确说明可能调用模型及计入现有额度。主进程先重新编译当前源码，若已经可编译则不调用模型。修复过程显示修复轮次/工具/构建次数，支持全局停止；成功后由用户打开预览，旧窗口不会因后台修改被替换。

最大预算为每次主动操作4轮模型请求、12次源码工具、5次构建和180秒。模型读取源码也占请求轮次，并非4次成功修改；同时受ModelService持久累计调用额度限制。轮次是先登记的模型调用尝试；预算、凭据或取消检查可能阻止请求实际发出，因此不等于真实供应商请求数或计费次数。实际请求数以ModelService用量和实测记录为准。供应商连接、鉴权或响应错误不自动付费重试。点击再次修复是新的主动请求，重新受到这些上限约束。

## 协调与成功判定

RepairRunner独立于原有源码生成回合，复用相同的list_files/read_file/apply_changes、ModelService和BuildService。编译修复输入为schemaVersion、requestId、projectId、planRunId、sourceRevision；运行修复另带runtimeReportId；模型不能提供宿主路径或编译配置。

起始与每个异步边界核验当前确认计划及完整源码快照，源码工具事务和构建请求标识均由受信层派生。模型读取必要文件、批量提交变更；每轮结束若源码内容变化，协调器重新真实编译，失败把受限诊断反馈给模型。只有匹配当前源码/计划的成功构建能结束为succeeded；模型口头称成功没有此权限。

模型直接结束但尚未通过编译，记no_progress；达到上限记limited；供应商失败记failed；用户停止记cancelled。总时限触发TIMEOUT/limited，供应商本身超时则failed/TIMEOUT。成功编译只证明构建通过，不证明运行时逻辑、功能保留或业务验收；需要实际页面和交互检查。模型被提示进行最小修复，但当前没有通用功能等价检查器。

## 持久记录与中断

每项目`runs/repairs.json`，旧schema 1可读，首次运行修复升级schema 2，最多50次/1MiB。记录固定计划哈希、请求指纹、起止源码版本、状态/阶段、模型与工具次数、工具事务引用、构建次数、最近构建尝试ID、受限诊断和固定错误码。最近尝试失败时buildId不代表存在成功产物；仍可从BuildStore取得之前成功产物。

首次请求意图和各次调用计数先落盘，再发请求或执行动作。不保存模型原始消息、工具参数、API Key或内部异常。诊断仅允许编译器固定消息和有效虚拟路径；编译器增加消息时需同步审查存储白名单。写入使用临时文件/fsync/重查/rename，拒绝损坏、未来格式、链接、陈旧计数及已观察到的记录消失；终态记录不可变，同一记录完全相同可幂等返回。归档后只允许结束既有运行，不能开启新运行。

保存若报告提交不确定，仅在重新读取的同ID完整记录与本次预期深比较一致时确认成功；读取失败或不一致保留原异常。其他保存错误同样立即停止，不再猜测性改写为failed。磁盘若仍是running，之后显示interrupted且不会自动继续付费。

进程重开时，无活跃操作的running显示为interrupted，不自动继续付费调用。同请求ID只返回已有状态，输入冲突则拒绝；元数据只提供已知进展，不实现完整断点续跑或回滚。取消后忽略迟到响应，不采用迟到构建；已经提交的源码保留，旧成功产物仍保留。

## 当前边界

编译修复与0.10.0的有限启动错误修复均只面向现有受控React前端。没有自动业务验收、任意依赖安装或后端执行。源码检查点已接入，持久业务数据及源码导出待实现。可信单写者磁盘协议及当前受测Electron隔离边界沿用[构建协议](CONTROLLED_BUILD.md)。

实际通过项目、失败记录和未覆盖场景以[本轮验证报告](evidence/2026-10-03/S3-02/bounded-repair/result.md)为准；本文件描述协议，不把尚未执行的测试写成验收通过。
