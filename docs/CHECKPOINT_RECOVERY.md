# 检查点与中断恢复协议

日期：2026-10-03。内部版本0.9.0；D-028、S3-03、FR-008/009、AC-010/011。实现和本机证据见[验证报告](evidence/2026-10-03/S3-03/checkpoint-recovery/result.md)。

## 源码检查点

`source/workspace.json`内的原子提交历史就是检查点的唯一来源，不另建可能与源码不一致的快照副本。revision 0表示初始空源码；每次受限工具修改保留此前完整快照，记录请求、确认计划绑定、文件哈希与变化路径。历史界面只传文件清单和元数据，文件内容仍通过既有只读接口查看。

恢复请求携带项目、原请求ID、计划ID、当前源码版本、目标版本。后端核对当前确认方向、全部源码历史、生成/修复记录和构建产物；旧计划的源码不能直接恢复到新方向（初始空源码除外）。恢复把目标完整文件树写成**单调递增的新版本**，保留恢复前代码、已保存产物及所有历史回执。不拆成多个工具修改，所以大量文件的增删不会留下半棵树。每批模型工具仍限32文件，可信恢复最多涉及128旧文件和128目标文件的并集。

同一恢复请求精确重放只返回已提交回执；不同输入复用ID被拒绝。若响应丢失后用户已修改确认方向或归档项目，先只读核对已提交回执，能够确认成功，不发起新写入；没有回执才要求当下确认有效。未确认恢复在本次工作台页面导航期间保持同ID，避免重复创建版本。进程退出后的恢复记录可从检查点历史核对。

继续支持0.8.0的schema 1源码记录；首次恢复才原子升级为schema 2，schema 2区分普通修改与恢复，并保存目标快照哈希。读取时逐步重放验证全部快照与请求，损坏、未来版本、路径链接、哈希不符均拒绝。旧应用无法读取schema 2，因此执行恢复后应继续用0.9.0或更新版，不能把降级启动称为数据迁移回退。

当前容量仍为每项目40次源码提交、128文件、源码树2 MiB、记录16 MiB；恢复也占一次提交，达到任何容量上限时拒绝新增修改/恢复，保留全部记录。此版本尚未提供历史压缩或轮换。目录边界和可信单写者模型沿用[SOURCE_TOOLS_PROTOCOL](SOURCE_TOOLS_PROTOCOL.md)，不是完整系统沙箱或损坏磁盘备份。

## 构建意图与结果

新增`runs/build-attempts.json`，schema 1，最多100条/1 MiB。每条保存请求ID、源码版本与哈希、确认绑定、起止时间、状态、固定诊断和错误码。编译前先原子保存running意图；成功产物仍由`runs/builds.json`保存，随后才保存succeeded。失败和取消也记录，原成功产物不被覆盖。

重启核对同ID实际产物及全部绑定：匹配的产物使遗留running转为succeeded，没有产物则为interrupted。成功记录缺产物、绑定不符、失败终态却存在同ID成功产物都被拒绝。相同ID的失败/取消只返回原结果，相同ID的中断明确请求用户新建构建操作，不自动重编；新ID才编译。旧0.8.0只有成功产物的记录仍兼容。

日志或产物在rename之后发生异常时，只在读回的完整记录与预期一致时确认成功；不确定而无法核实时停止，不猜测失败再覆盖终态。源码生成协调器也补齐了同样的保存不确定处理。

## 中断后的用户动作

工作台核对全部生成/修复历史的起始版本、工具请求回执及成功构建引用；界面展示各类最近运行。未被本进程执行的running在读取时投影为interrupted，模型运行日志本身不为显示而改写；构建意图则按上述证据持久化最终判定。

工具ID对应源码提交时显示已确认版本；未找到提交的工具可能是读取、拒绝或尚未执行，不能直接推断“写入失败”。构建成功只表示实际编译产物存在，不提升任务的业务验收状态。现有预览不会因回退自动替换，用户重新构建再打开。

模型响应中断不重发；已持久化的调用次数与未知用量保持。用户在核对后点击“继续生成源码”或“自动修复并构建”，才从当前确认计划和当前源码开始新一轮，继续受原累计额度和每轮限额约束。仍不保存原始模型消息或密钥。

生成、修复和构建的主进程入口都先执行一致性核对：例如新进程看到源码文件缺失，但已有产物证明曾有源码时，拒绝把它当空项目收费重新生成。恢复本身不调用模型，也不涉及项目之外的路径。

## 业务数据与验证范围

代码恢复只写源码记录，不写`data/`、需求/确认、用量、文章或图片，不承诺恢复预览窗口的临时状态。数据库结构迁移、独立数据备份/恢复、完整生成博客和跨平台流程仍属后续工作。强制终止验证覆盖当前Mac上的受控Node进程SIGKILL，不能代替断电、硬件损坏、Windows或恶意本地进程测试。
