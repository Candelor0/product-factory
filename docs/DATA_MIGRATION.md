# 生成应用数据结构与受控迁移

对应FR-008、AC-010/011/014、S4-02与D-034。0.15.0新增可选业务结构声明；本文描述实现约束，实际通过项目见本轮[验证报告](evidence/2026-10-05/S4-02/data-migration/result.md)。工作台首页与侧栏保持原布局，入口位于开发计划的「应用数据结构」。

## 结构声明

源码文件`src/data-schema.json`声明版本和有限类型。没有文件表示未声明的旧结构（业务版本0），不等于无数据。声明版本1—1000，最大64 KiB，类型节点最多256个、嵌套深度8；迁移步骤最多64个。既有JSON容量、危险属性名、普通文件与路径限制仍适用。

```json
{
  "schemaVersion": 1,
  "version": 1,
  "keys": {
    "posts": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "title": { "type": "string" },
          "published": { "type": "boolean" }
        },
        "required": ["title", "published"]
      }
    }
  },
  "migration": {
    "fromVersion": 0,
    "steps": [
      { "operation": "renameKey", "from": "articles", "to": "posts" },
      { "operation": "addField", "key": "posts", "field": "published", "value": false }
    ]
  }
}
```

类型仅有string、number、boolean、null、array/items、object/properties/required。顶层声明的数据项均可缺省，因此新库可从空对象开始；存在的数据项和嵌套对象不允许未声明字段，required约束对象中的必填字段。结构哈希只含规范排序后的version/keys，不含迁移步骤；预览另绑定整个当前源码快照，修改步骤也会使旧预览失效。同版本改变字段结构需要新版本，不能静默兼容。

## 操作与确认

只允许从当前业务版本n迁移到n+1，迁移声明的fromVersion必须匹配。不执行JavaScript、SQL、宿主命令、强制类型转换或跨多个版本跳迁。

| 步骤 | 规则 |
| --- | --- |
| renameKey | 重命名顶层项，源必须存在、目标必须不存在 |
| addKey | 新增不存在的顶层项，值必须符合JSON协议 |
| renameField | 对指定数组每个对象重命名字段；任一行缺源或已有目标即拒绝整次迁移 |
| addField | 对指定数组每个对象补缺失字段；已有字段保持原值 |

最终结果必须符合目标结构和全部数据容量限制。预览只显示版本、数据项名称及增删改计数，不把个人正文返回工作台或模型。确认前推荐使用独立备份；工作台需要勾选确认，关闭该项目持久应用（未保存编辑会丢失），重新检查项目、源码及数据，再把值、结构、回执和迁移前检查点原子提交。不会自动重开或调用模型。

预览令牌仅存在主进程内存，10分钟有效，一次只保留一个。数据/源码/项目变化、取消、丢弃或重启使未提交预览不可继续。确认结果不确定时用原令牌核对，存储回执保证同次操作不重复提交；不要把新预览当原请求重试。已提交成功的结果核对不再次关闭新打开的应用。

## 访问与回退

已有库必须与构建对应的结构哈希一致，才可持久读取/写入。没有声明的旧源码不能读取已声明的新结构，删除声明也不能绕过。临时预览/检查仍只使用临时内存，但写入同样验证声明；业务值不进入模型生成提示。新空项目首次打开持久应用可直接初始化声明结构，状态查询不创建数据目录。

仅保留最近一次迁移前的完整值和结构。回退前需要先将源码恢复到该结构；迁移后有任何成功业务写入或备份恢复，即拒绝这次迁移回退，即便值后来相同。回退追加新revision，不回退计数或旧回执，不操作源码、凭据、模型授权和用量。检查点在同一项目存储内，不是独立备份，后一次迁移会替换它。

磁盘旧schema1继续兼容，首次带结构初始化/迁移保存为schema2；回退到业务版本0也保留磁盘schema2。升级后的文件需要0.15.0或更新版读取。5份滚动历史、256回执、8 MiB记录容量仍保留；迁移前检查点额外占空间，达到容量则拒绝写入。

数据备份版本2携带结构定义/哈希；版本1按旧结构处理。恢复要求备份与现有存储的结构一致，并继续核对项目/storeId/源码内容；备份恢复不能用来改变结构。哈希仅用于一致性检测，不是签名或完整系统沙箱。

未覆盖图片、任意后端/SQL迁移、多步跨版本编排、损坏库重建、跨机器项目恢复、断电及双平台。结构检查不等于业务语义或完整博客验收。
