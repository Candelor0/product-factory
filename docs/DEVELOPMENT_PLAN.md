# 产品工厂分阶段技术开发手册

版本：0.2 · 更新日期：2026-10-05（D-037范围更新） · 状态：开发已启动，阶段出口保持约束

本手册描述开发方法与退出条件，不表示整体已经通过或取得发布资格。用户已明确授权开发（D-012）；基础模块按 D-014 在 S0 核实期间并行验证，但不取消 S0 出口。实际状态只维护在 [TASKS](TASKS.md)，不要重复维护完成率。

产品范围见 [PRD](PRD.md)，建议架构见 [TECHNICAL_DESIGN](TECHNICAL_DESIGN.md)，决策见 [DECISIONS](DECISIONS.md)，验收见 [ACCEPTANCE](ACCEPTANCE.md)，当前交接摘要见 [STATUS](STATUS.md)。

## 1. 防止上下文丢失的工作协议

每次新会话、上下文压缩后或换人接手，按以下顺序开始：

1. 读取 `STATUS.md` 的当前阶段、下一任务与未决问题。
2. 从 `TASKS.md` 核对真实状态、依赖、阻塞项及证据链接；与摘要冲突时，以台账和实物证据为准。
3. 读取本阶段手册、相关 PRD 需求、最近决策及上一轮失败证据。
4. 核对工作区实际文件和版本标识，确认未提交工作、运行中进程及待恢复状态，再执行最小可验证任务。

完成或暂停任务时，必须留下：

- 任务 ID、关联需求 ID、完成与未完成的具体内容、变更文件、版本/提交标识。
- 实际执行的验证步骤、环境、预期与实际结果、退出码和证据路径；未运行就写“未运行”及原因。
- 新决定写入 `DECISIONS.md`，范围改变同时更新 PRD 与验收矩阵，不能只留在聊天里。
- 更新 `TASKS.md` 的唯一进度记录，再刷新 `STATUS.md` 的简短交接摘要和下一个动作。

不能仅凭“模型说完成”、界面截图或一段最终回复把任务标为完成。没有测试适用的文档任务可以记录审阅与链接一致性检查；涉及运行时、数据或安装的任务必须有相应实际验证。

证据统一存入 `docs/evidence/日期/任务ID/运行编号/`，包含 `result.md`、必要日志与截图。`result.md` 写明需求、输入版本、执行环境、步骤、期望、实际、结论、已知限制。运行编号使用时间戳或 UUID；不要覆盖上一次失败证据。凭据、私人博客内容和个人文件路径在共享证据中脱敏。完整目录规范见 [证据规则](evidence/README.md)。

## 2. 阶段依赖与统一完成定义

推荐顺序：`S0 → S1 → S2 → S3 → S4 → S5 → S6`。每阶段设 3 个主任务，子步骤不另建任务 ID。阶段内按表中依赖推进；按用户确认的D-037，当前S5推进Mac，Windows任务S5-03保留但延后；Mac的S6功能与可用性验收可并行，不依赖S5-03。

阶段出口意味着该阶段所有必须项有证据、阻塞问题已解决或明确回退、相关台账已更新，不意味着用户必须逐项手工确认每个内部技术动作。用户已确认的范围和常规可逆实现不重复请示；超出已确认产品范围、涉及新的付费账号或新授权才单独说明。

首个真实验收案例为个人博客网站；文章管理、草稿/本地发布、标签分类与图片是建议功能，S0 冻结前需确认。DeepSeek 是首个必须验证的模型服务；其他国内供应商名单未冻结。用户已确认工作台托管一键启停和源码导出（D-015）；免环境独立启动包不进首版。

不预估未经验证的开发时长。遇到阻塞时记录可选处理、影响和下一检查动作，不能擅自跳过阶段出口，也不能把范围削减包装为完成。

## S0 · 技术可行性与范围冻结

**目标**：以最小验证确认技术路线能支持零配置安装、AI 开发闭环和个人博客用例，明确首版边界。

**入口**：用户授权进入开发；PRD 初稿已评审；能够取得两个上游的固定版本、许可信息与待验证资料。只有文档阶段时，以下试验不得提前执行并标记通过。

| 任务 ID | 具体任务与建议依赖 | 产物与适当验证 |
| --- | --- | --- |
| S0-01 | 范围与支持矩阵冻结。确认博客最小功能、DeepSeek 接入及其他供应商优先级、托管/独立运行边界、当前Mac版本与架构，Windows矩阵按D-037留后续；登记上游 SHA、许可、来源文件映射；冻结验收样本和性能预算。无阶段内依赖。 | 评审后的 PRD、支持矩阵、决策记录、带参数的验收样本。通过文档审阅验证范围与需求 ID 一致，未决项有负责人/后续动作。 |
| S0-02 | 桌面运行时与执行边界验证。依赖 S0-01。做最小桌面安装试验，证明无需系统 Python/Node/Git 即可启动模板、写入数据并重开；验证受信运行时与生成源码的边界、路径逃逸、端口鉴权和取消；比较受管后端与任意后端方案。 | 当前Mac支持矩阵的可行性记录、工具链打包清单、执行边界决定；Windows单列延后。测试用例覆盖干净环境启动、目录逃逸拒绝、预览无宿主权限、持久数据重启保留。尚无签名条件时明确只能证明内部可行性。 |
| S0-03 | Blueprint 复用与模型能力验证。依赖 S0-02 完成，以其打包与执行边界结论为输入。对比保留 Python worker 与 TS 迁移成本；验证 DeepSeek 连接、流式/结构化输出或工具协议、错误与用量；核对上游流程转为产品阶段所需新增工作。 | 适配协议草案、方案对比和小样本实测。使用固定需求对照字段、失败与恢复；保存模型版本、配置、请求用量。测试 Key 不入库、不入证据。 |

**出口证据**：技术决策明确“采纳/放弃/待阻塞”，首例与标准模板范围相容，当前Mac支持矩阵的零环境配置有实际可行性证据；Windows按D-037延后，不免除日后独立验证；当前范围不能实现时，不进入大规模界面与执行器开发。技术路线可在此更换，所有建议版本号到此才锁定。

**失败/回退**：Python 打包失败先检查依赖、资源和原生构建，再决定迁移；受控模板覆盖不了已确认博客功能则返回范围讨论或验证更强隔离；签名、模型能力或平台缺口单独记录，不用开发机成功掩盖问题。

**交接**：固定版本、真实测试环境、选型理由、拒绝方案、未解决约束、S1 可实施接口契约。关联 FR-001、002、006、007、011 及 NFR-001—006。

## S1 · 桌面基础与模型接入

**目标**：可安装启动、配置模型、创建本地项目并可靠保存，形成后续功能的统一基础。

**入口**：S0 出口通过；系统支持矩阵、运行时组织、凭据方案与首批 provider 已冻结。

| 任务 ID | 具体任务与建议依赖 | 产物与适当验证 |
| --- | --- | --- |
| S1-01 | 桌面壳与项目存储。建立主进程/renderer 窄接口、项目清单、数据库迁移、文件产物目录与事件协议；区分源码和业务数据目录。依赖 S0。 | 可启动的开发版本、schema 与目录契约。验证项目创建/重开、崩溃后状态读取、中文及空格路径、跨项目引用拒绝。 |
| S1-02 | 凭据保管与供应商适配。依赖 S1-01。实现 DeepSeek 首个 adapter、加密保管、连接测试、模型能力记录、统一错误分类；预留经验证的其他国内供应商接口。 | 模型服务与凭据模块。实测有效/无效 Key、限流或模拟限流、网络中断、凭据服务失败；检查 renderer、日志、导出候选目录无明文 Key。 |
| S1-03 | 首次启动与错误引导。依赖 S1-01/02。完成欢迎页、模型配置、项目创建、运行资源检查与可理解错误处理；明确哪些调用会产生费用。 | 首次使用流程与错误文案。按验收矩阵记录从安装到连接成功所需步骤；新用户无需终端或修改环境变量。 |

**出口证据**：在已冻结的平台范围内，打开软件、填写 Key、建立项目、退出重开全部可验证；设置问题能在界面处理；无法连接模型时不丢项目。

## S2 · 需求方案与 UI 确认

**目标**：把对话变成可版本化的需求与设计，并在用户确认后才进入自动开发。

**入口**：S1 出口通过；至少一个 provider 可用；阶段协议与上游映射可实施。

| 任务 ID | 具体任务与建议依赖 | 产物与适当验证 |
| --- | --- | --- |
| S2-01 | 需求澄清与 PRD 版本。依赖 S1。将用户输入整理为目标、页面、行为、数据、边界与验收点；支持修改、未知项和可读摘要，保存版本而不覆盖历史。 | 对话到需求的工作流。用博客需求验证未回答内容不会变成已确认功能；更新需求时旧版本仍可查阅。 |
| S2-02 | Blueprint 阶段协议与规则编排。依赖 S2-01。实现分析适配、统一持久状态、结构化结果；先区分普通 Web 与 Agent 需求，再选适用规则。把 starter-kit 的规则转为阶段提示、产物 schema 和检查项，拆清模型判断与实测。 | 可追溯的方案生成与差距数据结构。验证 worker 失败、格式错误、重复事件和重启；普通博客不被强制加入 Agent 组件，适用的 Agent 案例与上游能力对照。 |
| S2-03 | 页面方向与方案确认。依赖 S2-01/02。提供生成应用的页面结构、视觉方向、必要的低成本预览及确认按钮；记录确认内容的版本/哈希。另交付工作台自身的高保真原型和组件样式规范供审阅。需求或方案实质变化时失效相应确认。 | 工作台对话、阶段与方案视图。检查可读性、键盘操作、加载/空状态、间距和字体一致性、视口溢出遮挡；验证未确认不能自动启动编码、确认与实际执行版本一致。首版建议先完成浅色主题。 |

**出口证据**：用户能理解并确认博客做什么、有哪些页面、页面大致样式及数据；开始开发绑定具体需求与方案版本。美观性依据 [ACCEPTANCE](ACCEPTANCE.md) 的视觉检查项和真实预览评审，不能以“组件库已接入”代替。

**失败/回退**：模型返回不完整方案则保留可用部分并继续澄清；Blueprint 中断可以恢复或重跑未完成阶段；确认内容改变时回到对应确认点，不偷偷继续旧任务。

**交接**：首例已确认需求/方案快照、规则来源、状态迁移图、确认失效规则和失败样本。关联 FR-004、005、009、012，NFR-001、003、006。

## S3 · 编码执行闭环

**目标**：真正生成和修改代码，运行可信检查，在有限修复循环中做出可启动的博客版本。

**入口**：S2 出口通过；需求与页面方向已确认；S0 冻结的执行边界具备实现与负向测试方案。

| 任务 ID | 具体任务与建议依赖 | 产物与适当验证 |
| --- | --- | --- |
| S3-01 | 标准模板与工具执行器。依赖 S2。建立源码、业务配置与可信工具链；实现结构化文件读写、候选副本、写入前基础检查点、构建和最小运行入口，保护运行时和测试标准。 | 可修改的标准工程与工具协议。验证路径穿越/符号链接拒绝、未知命令拒绝、构建配置保护、项目互不写入、无系统运行时仍能构建。 |
| S3-02 | 代码生成构建修复循环。依赖 S3-01。按任务生成变更、类型与构建检查、健康检查及必要业务验证；错误反馈自动修复，但设次数/时长/用量上限；只发布通过检查的候选版本。 | 最小端到端开发闭环。以博客完成确认的文章行为；人为注入类型错误或缺文件，验证修复/到限暂停，最后可运行版本不被失败候选覆盖。 |
| S3-03 | 检查点与中断恢复。依赖 S3-01/02。强化持久事件、文件事务提交、取消令牌、去重、恢复判定；保存模型输入版本、工具结果和恢复动作。 | 可验证的恢复机制。于模型流式输出、文件提交、构建和阶段切换中中断进程；重启后不重复覆盖文件、不伪造完成、不无限重发计费请求。 |

**出口证据**：从确认后的博客需求生成可运行版本，有真实构建/功能证据；能自动修复至少一个受控错误，无法修复时可解释暂停；执行边界负向测试通过。这里的运行入口供检查使用，完整用户预览与启停体验在 S4 完成。

**失败/回退**：失败候选留在独立副本，恢复到最近可运行版本；修复到限立即停止；不允许通过改写测试、关闭隔离或放开 Shell 来使流程“通过”。若确认需求超出模板能力，返回设计决策和用户范围讨论。

**交接**：源码与模板版本、执行器接口、修复上限、检查点格式、故障注入记录、尚未覆盖的代码类型。关联 FR-006、008、009，NFR-003、004、006。

## S4 · 预览迭代与恢复

**目标**：用户能使用本地博客、提出修改并看到结果，数据在重启、迭代和恢复中可靠保留。

**入口**：S3 出口通过；至少一个通过检查的博客版本；运行和数据契约已明确。

| 任务 ID | 具体任务与建议依赖 | 产物与适当验证 |
| --- | --- | --- |
| S4-01 | 本地启停与隔离预览。依赖 S3。区分候选预览与已构建的本地交付版本；完成一键启动/停止、内嵌预览、打开本地浏览器、端口冲突处理、退出与孤儿进程恢复；按已确认运行方式处理关闭工作台。 | 可实际使用的本地应用流程。测试交付构建在停止与重启后仍可启动、端口占用、重复启动、服务崩溃、Origin/Host/会话边界；普通预览页不能调用桌面 IPC 或读取 Key，不能仅以开发服务器成功作为部署通过。 |
| S4-02 | 迭代差距检查与数据保留。依赖 S4-01。自然语言修改博客页面和行为，显示进度与结果；需求到行为的差距报告附证据；数据库与上传图片独立于源码，迁移前备份，回退语义清晰。 | 版本迭代和数据恢复流程。创建文章与图片后改主题、改字段、重开应用；验证保留内容；让一次迁移失败并恢复；差距报告能区分“缺少实现”和“未验证”。 |
| S4-03 | 用量预算与成果导出。依赖 S4-01/02。分别记录开发与应用 AI 调用；用量未知时明确标注，价格估算关联配置版本；导出源码、文档、运行契约，数据导出独立选择且排除凭据。 | 用量面板与可检查导出包。验证超限暂停、取消与请求不确定状态、敏感信息扫描、导出清单完整性；仅在独立运行已确认范围内增加独立启动验证。 |

**出口证据**：首例博客能一键本地使用、停止再开数据仍在、自然语言修改后预览更新、失败能恢复；导出结果与其承诺的运行方式一致。“本地发布文章”绝不触发公网托管。

**失败/回退**：端口问题自动选择可用端口并更新入口；数据迁移失败还原备份；费用未知不显示虚构准确金额；导出失败不删除原项目；当前工作台若不能支持独立运行，界面必须如实说明。

**交接**：完整首例录像/截图与操作记录、数据恢复证据、进程生命周期策略、用量与导出限制。关联 FR-007、008、009、010、012，NFR-001、003、004、006。
