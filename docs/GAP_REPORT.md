# 需求—实现—验证差距报告

版本：0.16.0 · D-035 · FR-012 / AC-015 · S2-02 / S4-02

报告读取工作台已确认的开发计划、源码快照、构建和启动记录，不调用模型。每个页面、功能、数据和验收条目保留原计划ID；原计划本身不会因生成了文件或编译通过而改成完成。

## 三类信息

- **源码线索**：当前文件与需求的声明关联。文件存在只能说明有可查看的实现线索，不能证明行为正确；无关联也不能推断功能不存在。
- **技术证据**：当前版本的成功构建、固定时间内启动观察及错误类别，独立展示。没有启动错误不等于操作或业务验收通过。
- **用户核验**：用户实际检查后填写操作步骤、预期、实际现象，并选择关联文件。可记录通过、未通过或确认缺少实现，来源明确为用户，不冒充自动测试。

不显示完成百分比。用户记录通过须有当前成功构建和至少一个实际存在的关联源码文件；未运行检查或尚无实现可记录缺少实现。每次核验都追加记录，最新同计划同任务的记录用于报告；旧记录保留在本地。当前界面展示每项最新记录，完整历史浏览、独立报告导出和交互回放尚未实现。

## 源码关联声明

源码生成提示要求按实际改动维护可选的 `src/requirements.json`：

```json
{
  "schemaVersion": 1,
  "planRunId": "当前开发计划UUID",
  "requirements": [
    { "taskId": "F001", "files": ["src/app.tsx"] }
  ]
}
```

只允许这些字段。最多200个不同任务，每个最多32个不重复路径；任务必须属于声明所绑定的当前计划，路径必须符合既有src路径协议，不能指向清单本身。清单格式、版本、计划或任务不合法时整份标为不可用，不执行其中内容，也不信任任何“通过”字段。路径不存在时提示关联文件缺失，不自动将业务需求判为缺失。旧项目没有清单仍能查看报告并人工关联当前文件。

## 版本绑定与保存

每份记录绑定项目、计划ID和输入/产物哈希、源码revision和快照哈希、构建ID和产物哈希。需求、源码或构建变化会让原结论过期；即使代码回退成相同内容，也需要重新核验。清单无权修改用户核验结果。旧计划对应的源码不能直接作为新计划实现来记录通过。

表单打开后固定待核验版本。刷新发现变化时须按新版本重新检查；不会把旧表单自动绑定到新版本。重复保存用同请求ID核对原请求；同ID不同内容拒绝。结果不确定时保留同请求核对，不通过重新保存制造重复记录。

本地存储为项目 `runs/gap-evidence.json`，与业务数据、源码和凭据分开。schema 1，最多500条记录/4 MiB，不自动淘汰旧证据；超过限额保留旧文件并停止追加。严格解析版本/字段/身份/哈希，独立普通文件检查、原子替换和读回核对，损坏不默认为空库。步骤、预期和实际各不超过2000字符且不能为空，不接受控制字符。

记录接口只提供给受信工作台，生成应用和模型工具没有写入权限。仅扫描填写内容中的常见凭据模式和已配置Key，不自动读取业务数据库或发送内容给模型。请只记录操作现象，不填写凭据或个人业务正文；有限扫描不能识别所有私人内容。

## 当前边界

这是一份有版本绑定的差距报告，不是自动业务测试器。没有自动交互回放、完整Blueprint分析worker或对任意外部仓库的分析；功能核验结论来源于用户实际观察，产品工厂无法据此独立证明所有业务语义。后续自动开发主流程可复用报告结构，但不能让模型自行写“用户通过”。
