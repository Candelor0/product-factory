## 产品背景与问题

现有两个项目分别解决架构推导和开发流程指导问题，但还不能作为一个普通用户安装后直接操作的软件使用。

| 来源 | 调研确认的当前能力 | 本产品拟采用的部分 |
| --- | --- | --- |
| [agent-blueprint](https://github.com/hubooooooo/agent-blueprint) | Python 引擎生成方案和差距报告，具有阶段保存与续跑机制，包含组件知识和参考实现 | 需求分析、组件判断、架构设计与差距检查 |
| [ai-product-starter-kit](https://github.com/hubooooooo/ai-product-starter-kit) | 文档和规则定义从 PRD 检查到开发、前端、上线、收尾的流程，依赖外部编码 AI 执行 | 阶段流程、工程约束、验收与交付规则 |

原项目代码与说明的阅读不等于真实运行验证。本产品需要新增桌面工作台、项目管理、模型接入、代码执行、运行预览与安装分发能力。starter-kit 没有可直接复用的独立执行引擎；其公网部署建议不进入首版。

用户面临的主要问题是环境配置困难、多个工具之间切换、看不懂开发状态，以及生成结果是否真正可用缺少证据。产品应把这些工作整合成可以观察、修改、恢复和查证的流程。

## 产品目标与用户

首版目标是让用户完成“描述想法 → 确认需求 → 确认页面方向 → 自动开发与检查 → 本地使用 → 对话修改”的闭环。成功以生成应用的真实任务完成情况衡量，不以生成代码量或页面截图数量衡量。

| 用户 | 目标 | 需要的产品支持 |
| --- | --- | --- |
| 项目发起人 | 快速验证想法，持续修改自己的工具 | 项目历史、明确范围、快速预览、可检查和可导出成果 |
| 非技术个人用户 | 用自然语言做出能用的小应用 | 引导式配置、易懂的确认项、一键运行、可恢复错误 |

不虚构用户访谈样本、转化率、市场规模或商业收入。首版暂无收费、团队订阅和商业化指标要求，是否商业发布单独决策。

## 首版范围

### 必须覆盖

- 可安装的本地桌面工作台，当前覆盖已冻结并经验证的 macOS 设备组合；Windows 按 D-037 延后，不是当前 Mac 发布前置条件。
- 在线模型配置与连接检查、项目保存与恢复、自然语言需求澄清。
- PRD 与架构方案生成、页面方向预览与确认、自动编码和受控执行。
- 自动运行必要检查、有限次数修复、预览、用户修改、检查点恢复。
- 有持久数据的本地 Web 应用启动、停止和再次使用。
- 成果源码和运行说明导出、脱敏诊断信息、真实验收记录。
- 对工作台生成项目进行需求与实现差距检查，并区分静态线索与运行证据。

### 首版建议限制

生成应用首先采用少量受支持模板和统一技术栈，优先覆盖表单、列表、看板、小型数据展示，以及使用已配置模型服务的简单 AI 文本功能。复杂第三方登录、支付、任意外部服务、多用户权限体系和任意技术栈不作为首版稳定承诺。

用户始终可以表达超出范围的需求；系统应解释限制并提供可实现的简化方案，不能假装已经实现。具体模板与首个用户案例在 S0 确定。

### 后续版本

Windows 适配、安装及发布验收按 D-037 暂缓，保留为后续工作，不标为完成。公网发布、移动 App 和桌面软件生成、离线模型、多人协作、云同步、插件市场、任意现有仓库的完整接管属于后续范围。导出源码属于首版；用户于 2026-10-02 确认由工作台管理启停，免环境独立启动包不进入首版（D-015）。

## 主流程与确认点

1. 用户安装并打开工作台，直接在中央输入想法并创建本地项目；过往项目只在侧栏，新建时不必先填项目名称或配置模型（D-023）。
2. 首次需要整理需求时，引导用户配置供应商/API Key；已有配置时可直接调用。随后通过少量有针对性的问题澄清目标、页面、数据和边界。高级配置仅在需要时展开。
3. 系统形成可编辑需求摘要，展示首版范围和暂缓事项，由用户确认。
4. 系统展示页面方向和主要交互草案，由用户确认或修改；草案明确标记尚未接入真实功能。
5. 系统自动生成代码、准备依赖、启动应用、执行检查并尝试修复。界面显示当前任务、已完成步骤和失败原因。
6. 用户在预览区操作应用，提出修改；系统生成新版本并验证相关功能，保留可回退检查点。
7. 用户通过工作台启动和停止已构建的本地应用，或导出成果。最终验收覆盖数据保存、重启和主操作。

需求与页面方向确认必须关联版本。后续变化若改变主要页面、数据模型或已确认范围，应展示变更摘要并重新确认受影响部分；普通样式调整和修复在已有授权范围内推进。

暂停应停止继续调度新任务；正在执行的工具需要完成或安全终止后才显示已暂停。取消不应删除已经保存的项目。

## 用户故事与功能需求

下列条目定义完整首版要求；当前实现与验证状态见 TASKS，不因基础工作流可用就视为全部实现。P0 为首版必需；同一条目内明确标为后续的扩展不进入 P0。

### FR-001 首次安装与配置

作为非技术用户，我希望安装后就能开始，以免配置开发环境。

**优先级：P0。验收：**在干净的目标系统环境中安装启动，普通流程不依赖系统已有 Python、Node、Git 或 Docker；能完成模型配置并进入新建项目。必须存在用户可理解的安装或初始化进度及失败重试。应用初始化如需下载组件，应自动处理，不要求用户复制命令。普通操作系统安装授权仍可能需要用户处理。

### FR-002 模型连接与凭据管理

作为用户，我希望配置在线服务后确认它确实可用，以免开发到中途才发现接口不兼容。

**优先级：P0。验收：**支持首批经过验证的供应商；检查密钥、地址、模型和所需工具调用能力；无效凭据、额度不足、网络失败和能力不支持具有不同错误提示。配置可修改和删除。密钥不进入生成的前端、普通日志和导出源码。通用协议选项不能宣称兼容所有供应商。

用户已确认 DeepSeek 及其他主流中国供应商方向。DeepSeek 是首个必须验证的供应商；Kimi、智谱、通义千问、豆包可作为后续兼容验证候选，候选不是支持承诺。具体协议、模型和其他首发供应商名单由 S0 实测确定。建议支持自定义服务地址，并把预设供应商与通用连接方式分开标记。生成应用需要 AI 能力时，应建立独立、可撤销的服务授权，不能直接把工作台主密钥写入生成项目。

D-032实施补充：0.13.0提供绑定当前确认计划和模型连接的项目文本AI授权，在工作台明确用途及调用/token额度后生效；持久应用可用，临时预览与自动检查禁用。可撤销且与开发用量分账，修改连接后重新授权，Key不进入生成页面。详见[应用AI与预算协议](APPLICATION_AI.md)。

### FR-003 项目管理

2026-10-02根据用户实际体验修订（D-023）：首页始终为单一想法输入入口，历史/归档项目集中侧栏；新建无需先填名称，可由想法自动命名后再改。保留浅色，减少首页额外元素。

作为用户，我希望项目和成果持续保存在本地，以便下次继续。

**优先级：P0。验收：**可创建、命名、打开和归档项目；不同项目的数据、任务和运行端口互不混淆；重启后可恢复最近保存的内容。归档不等于删除，删除必须明确列出影响的数据。首版建议允许保存多个项目，同一时间只执行一个生成任务。

### FR-004 需求澄清与 PRD

作为用户，我希望系统帮我把模糊想法说清楚，并让我确认，以避免做错方向。

**优先级：P0。验收：**形成目标用户、核心任务、页面、数据、范围与可检验目标；区分用户明确需求、系统建议和待确认问题。用户可直接修改或通过对话修改。需求确认记录关联具体版本，不以默认选中或等待超时代替确认。

### FR-005 架构方案与页面确认

作为用户，我希望先看到页面方向，再让系统完整开发，以减少返工。

**优先级：P0。验收：**系统基于需求形成方案和开发任务，提供关键页面与交互草案；显示确认后的版本。技术细节默认收起，用户能够理解页面和功能取舍。未确认时不进入完整应用实现；预览草案不能显示为已完成产品。

D-020实施补充：开发计划从已确认版本整理页面、功能、数据与验收待办；改变版本后提示重新整理，未明确问题保留。规则整理成功不等于任务实现或验收通过。

2026-10-02用户反馈对当前外观不满意，并询问调整时机（D-021）。现有0.3.0视觉样式不视为用户认可的最终方案。后续用户明确要求减少AI套版感、降低信息密度，并参考设计网站优化页面（D-022）。本轮先聚焦工作台，采用简洁导航、按需展开详情、明确主操作；具体视觉方案仍需用户审阅。工作台原型/组件规范继续由S2-03、AC-020承接。

### FR-006 自动编码与执行

作为用户，我希望确认方向后由系统完成代码、运行和修复，以免转到其他编码工具手动接力。

**优先级：P0。验收：**内置执行链完成文件修改、受控依赖安装、构建和测试，记录任务和结果；失败时有限重试，达到限额后保存现场并给出继续、调整或回退选项。首版建议每个失败任务最多自动修复三轮，此数值需通过实测调整。执行器不能默认获得用户所有目录及工作台密钥。

D-024实施说明：内部受限工具实验支持源码文本的列表/读取/批量原子修改，绑定当前确认计划；尚未接入真实模型、构建或执行，不作为本需求整体完成。实现边界与证据见[SOURCE_TOOLS_PROTOCOL](SOURCE_TOOLS_PROTOCOL.md)。

D-025实施补充：在开发计划内可主动调用模型生成源码草稿，并查看保存的文件；最多4轮请求，允许取消，异常中断不自动重发付费请求。此增量只实现FR-006的代码生成部分，源码未构建或运行，验收状态保持未运行。

D-026实施补充：源码草稿可通过固定工具链构建为候选前端，并在受限独立窗口中预览；只支持随包React运行时及虚拟源码引用，不运行生成脚本或安装任意依赖。构建失败保留上一候选并显示诊断，不把编译通过当业务验收。

D-027实施补充：构建失败后可主动调用有限修复，最多4轮模型请求/12工具/5构建/180秒，受已有累计调用额度限制；先本地复检再决定是否需要模型。修复结果必须真实重新编译，失败保留旧产物，成功仍不代表业务验收。

### FR-007 预览与本地运行

作为用户，我希望直接操作做出的应用，并在以后重新打开使用。

**优先级：P0。验收：**支持打开预览、一键启动、停止和重新启动；端口占用能够自动处理或解释恢复方式。正式本地运行使用可重复构建的交付结果；仅开发预览服务运行不算验收通过。有数据的应用在重启后保留数据；停止后不遗留未标记的进程。

本地运行默认只允许本机访问，由工作台管理启停并支持源码导出（D-015）。关闭工作台时应明确提示受管应用将停止；后台常驻和免环境独立分发不进入首版。

### FR-008 修改与检查点

作为用户，我希望通过对话修改应用，并在改坏时恢复。

**优先级：P0。验收：**修改前保留检查点；每次修改关联需求、受影响文件与验证记录；可以恢复到上一可用版本。代码恢复与用户数据恢复必须区分。涉及数据库结构变化时，备份、迁移和回退行为需明确，不能因为回退代码悄悄删除新数据。

D-028实施补充：源码检查点历史可见，恢复前显示文件影响，恢复以原子新版本保留前后代码，不覆盖业务数据和确认记录；与当前计划不符的检查点拒绝新恢复。数据库迁移和独立数据恢复仍待S4验证。见[恢复协议](CHECKPOINT_RECOVERY.md)。

### FR-009 会话恢复与用量控制

作为用户，我希望中断后继续工作，也能知道模型调用的消耗。

**优先级：P0。验收：**重启后恢复阶段、已确认需求、任务、结果和失败位置；不会无条件重放已完成的有副作用步骤。显示调用次数、供应商返回的 token 用量和已配置预算；缺少价格或用量时明确未知，不显示虚假的精确金额。达到可执行的调用或 token 限额时停止新调用并保存。单次请求可能存在的计费边界须在技术设计中处理。

D-028实施补充：构建意图先落盘，重启核对源码提交与实际产物，未确认工具不自动重放。用户核对后主动继续新一轮；历史调用次数/未知用量保持。当前Mac前端流程已做指定进程中断验证，完整worker、数据库与双平台仍未完成。

D-032实施补充：开发累计调用限额保留，新增可选token预算；每个应用有独立累计调用/token额度。请求前落盘预留，合法usage结算；未知、取消和中断保留占用，不自动重发。旧未知记录不允许按零启用token限额，累计溢出持久阻断后续有限预算调用。预留不是供应商精确计费上限，当前无价格配置或金额估算。

### FR-010 成果导出

作为用户，我希望保留自己的成果，以便备份和后续维护。

**优先级：P0。验收：**导出源码、依赖锁文件、需求与方案、构建运行说明和项目清单；默认排除凭据、缓存、运行日志及个人数据库。需要导出数据时单独选择。缺少项目级服务授权时，导入或运行后提供重新配置提示。免环境独立启动包不进入首版（D-015）。

D-031实施补充：0.12.0新增当前源码与确认文档的ZIP维护包，含固定工具/运行时/SDK、真实依赖锁、文件清单与验证/重建说明。导出不调用模型，原生对话框选择新文件，取消不保存，不覆盖旧文件；默认不读取业务数据库和凭据。源码最后提交的计划来源与当前文档来源分别标记，不能据此宣称新需求已实现。维护者自备Node/npm重建，运行仍需协议宿主；尚无源码导入UI、独立服务或数据单独导出。详见[源码导出协议](SOURCE_EXPORT.md)。

### FR-011 跨平台体验与故障恢复

作为用户，我希望在承诺支持的平台上完成一致的安装、生成和运行流程。当前先交付 Mac，Windows 按 D-037 延后。

**优先级：当前 Mac 范围为 P0，Windows 延后。验收：**在当前承诺的 Mac 系统与架构组合分别验证安装、中文及带空格路径、端口管理、重启恢复、预览和卸载保留数据策略；离线、模型超时、磁盘不足等失败能定位到阶段且不损坏已保存项目。Mac 的安装、数据可靠性与体验标准不降低；Windows 恢复推进时单独完成同类验证，不能以 Mac 通过替代 Windows 验收。

### FR-012 差距检查与交付报告

作为用户，我希望知道哪些需求已实现、哪些还缺失，而不是只收到“开发完成”。

**优先级：P0，限定工作台生成的项目。验收：**每项核心需求关联实现和验证结果，生成已完成、未完成、未验证列表。保留原 blueprint 架构差距分析价值，但将静态扫描结果标为线索；静态信号覆盖率不能直接作为产品完成百分比。普通非 Agent Web 应用不强制装配全部 Agent 组件。任意外部仓库接管属于后续扩展。

## 界面与交互要求

建议采用中文优先、浅色为首个完整主题、适度留白的桌面工作台。深色主题可以后续补充，颜色和品牌名称尚未固定。技术日志不占据主要操作区域。

| 界面 | 主要内容 |
| --- | --- |
| 初次配置 | 供应商、API Key、连接检测和继续按钮，高级选项收起 |
| 项目首页 | 中央想法输入与开始按钮；无论有无项目均为同一入口，过往项目仅侧栏展示（D-023） |
| 需求与页面确认 | 可编辑摘要、范围、页面草案、待确认项和明确的确认按钮 |
| 开发工作区 | 项目导航、对话、阶段进度、应用预览，可调整面板宽度 |
| 成果与历史 | 本地启停、版本检查点、验收报告、导出 |
| 设置与诊断 | 模型设置、数据目录、限额、脱敏诊断包 |

主操作要用“开始制作”“打开应用”“继续修复”等用户可理解的语言。每个页面具备空白、加载、成功和失败状态。运行中允许随时查看预览、暂停并提交调整，不因长任务阻塞整个界面。

设计建议以 1280×800 桌面尺寸为主要验收视口，并验证 1024×768 下核心操作可达。键盘可完成主要流程、焦点可见、状态不只依靠颜色、文本支持放大。生成 Web 应用还应验证窄屏布局；这不代表首版生成原生手机 App。

工作台自身的美观与生成应用的页面方向是两项不同验收。S2 应交付工作台主要页面的高保真原型与基础组件样式规范，供用户审阅；检查字体层级、间距、配色、加载和错误状态的一致性，以及约定视口下的溢出、遮挡和文字截断。0.5.0已有可运行单输入首页、真实截图与[基础视觉规范](design/WORKBENCH_VISUAL.md)；用户审阅与完整可用性验收仍待完成，见S2-03证据。

## 成功指标与验收方法

| 指标 | 定义 | 建议首版目标 |
| --- | --- | --- |
| 核心成功指标 | 在约定参考案例中，从空项目到可重启、有数据持久性的本地应用，核心用户操作全部通过 | 当前按 Mac 的参考案例 × 每案重复次数单独统计，逐次记录成功与失败；具体样本、次数和成功门槛在 S0 冻结，不从原双平台口径自行换算。个人博客须在当前 Mac 支持范围通过，且不得丢失数据 |
| 环境门槛 | 干净系统在不手工安装开发环境、不输入命令的情况下完成核心流程 | 每个支持平台至少一份完整通过记录 |

| 中断恢复 | 关键阶段强制终止后，重启能恢复状态且不重复执行已完成副作用 | 指定中断点全部通过 |
| 文档可查证 | 完成任务是否关联真实证据 | 100% 已完成任务可查证 |

用户已指定个人博客网站为首个实际案例。建议另外使用小型 CSV 数据展示、AI 文本摘要工具作为能力补充案例。D-037只调整平台顺序，不批准新的样本数量或通过比例；原双平台12次指标不作为当前Mac验收分母，历史口径保留在决策记录。模型、提示词和模板版本需要固定并记录，不能更换困难案例来提高成功率。Mac干净安装、真实案例和非技术试用仍须实际完成，不以暂缓Windows代替这些出口。

### 首个案例 个人博客网站

用户已确认应用类型，以下具体功能是验收范围建议，尚未逐项确认：博客首页、文章列表与详情、文章新建编辑删除、草稿与站内发布状态、分类或标签、封面图片、本地管理入口、文章与图片持久保存。文章发布仅改变本地博客中的可见状态，不涉及公网部署。

验收时实际创建文章、上传图片、保存草稿、发布并查看、编辑内容，然后停止应用、重启电脑或工作台后重新启动，检查文字、状态、分类与图片仍然正确。再用一句话要求修改页面样式，确认已有内容未丢失。首版不默认加入评论、访客注册、在线支付、跨设备同步或第三方图床。

指标用于本地测试和自愿试用。首版不默认上传项目或遥测数据，不虚构活跃用户和满意度统计。

## 技术边界与依赖

建议架构由桌面界面、可信协调器、模型适配器、项目持久存储、隔离执行器、预览进程与受管运行环境组成，详见 [技术方案](TECHNICAL_DESIGN.md)。具体桌面框架和原 Python 引擎打包策略先经 S0 验证再定案。

“只填 API Key 即可上手”指使用已支持能力的基础流程不需要额外开发环境或编码工具。网络可用、模型账户有额度、操作系统允许安装是必要条件。用户应用如额外集成其他外部服务，可能需要独立凭据；这些不应悄悄成为首版基准案例的前置条件。

本地存储不代表所有数据都不会离开本机。需要调用模型时，相关需求与必要代码片段会发送到用户所选供应商，应在首次配置时清楚说明；不扫描和上传与项目无关的文件。

## 风险与处理建议

| 风险 | 影响 | 处理与触发条件 |
| --- | --- | --- |
| 任意技术栈生成质量不可控 | 安装和修复失败增多 | 首版限定受支持模板，S0 冻结参考案例；超出范围明确说明 |

| 上下文丢失导致重复或遗漏 | 项目无法接续 | 持久需求与任务，版本化确认，恢复时核实实际产物 |
