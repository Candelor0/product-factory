# 页面启动检查与运行错误反馈

日期：2026-10-04。0.10.0、D-029，覆盖FR-006/007、S3-02及S4-01的当前前端子项。

## 操作与结果

「构建并预览」先编译，再在隐藏的隔离窗口观察启动；发现错误或用户取消时保留旧窗口及其临时数据。当前窗口已打开同一构建时只聚焦，不重复观察、不重置数据。用户也可点击「检查当前页面启动」，新建隐藏候选并在结束后销毁，不改变可见窗口。

主进程在页面加载后执行活性检查，观察1200毫秒并再次核对响应。总截止12秒，单次活性检查750毫秒。页面中的计时器、ready消息或模型文本不能决定通过。`observed`仅表示本次有限启动观察未发现错误，不等于业务验收、完整交互测试或未来不会出错。加载前无限循环由总截止处理，加载后无响应由活性检查处理。

`issues`只列固定类别：Reference/Type/Range/Syntax错误、一般脚本错误、异步拒绝、React渲染错误、控制台错误、资源失败、渲染进程退出、无响应及启动超时。错误message、stack、Promise reason和控制台原文不保存、不传给工作台或模型。实际页面可伪造负向信号或吞掉错误，因此这是一组保守观测，不能充当任意恶意源码的正确性证明。

已打开窗口的晚到错误继续记录。状态优先选择当前源码与确认绑定的报告，再按最近活动选择；新隐藏检查不会遮住同版本可见窗口随后出现的错误，旧源码的晚到错误也不会覆盖当前版本报告。首次错误会快速终止候选，故类别列表不保证穷尽全部异常。

## 有限修复

当错误报告与当前源码、构建及确认计划一致时，用户可以点击「尝试修复并检查启动」。只有主动点击才可能消耗模型额度，沿用4轮模型请求、12次源码工具、5次构建、最多5次启动检查和180秒上限，以及已有累计额度。

协调器先编译并复现错误。首次启动未复现时结束为`no_progress / RUNTIME_NOT_REPRODUCED`，零模型请求，明确提示尚未验证原交互错误，不声称修复成功。可复现时将固定类别反馈给模型；每次源码内容改变后重新编译，再由独立隐藏窗口检查。只有修改后匹配的编译产物和启动观察都通过，才记录有限修复成功。交互场景不会自动回放，仍需用户实际检查。

取消和到限保留已提交源码与旧预览；失败不回滚已有数据。没有自动付费续跑。同请求ID读取既有回执，不能重放付费请求。模型仍只可调用`list_files/read_file/apply_changes`，无宿主命令、安装依赖或运行后端的接口。

## 记录与恢复

每项目`runs/runtime-reports.json`为schema 1，100条/1MiB，达到容量后明确拒绝新记录，暂不轮换。绑定报告ID、源码版本/哈希、构建ID/产物哈希、计划及确认哈希；先保存`observing`意图，再启动窗口，最后保存`observed/issues/cancelled`。新进程把无活跃观察的`observing`保存为`interrupted`，不自动启动页面或调用模型。

使用临时文件、fsync、重查与rename；拒绝链接、损坏、未知格式、陈旧状态和已观察过的记录消失。不确定提交只在完整同ID回读一致时确认。窗口事件回调保存失败不会形成未处理异常，但后续状态和工作操作会明确报错，不能继续显示旧成功结果。

`runs/repairs.json`首次写入运行修复时升为schema 2，增加初始错误报告与最近检查报告引用；旧schema 1可读。旧版0.9.0不支持新运行修复记录，应继续使用0.10.0或更新版本。恢复协调器验证运行修复成功必须对应真实保存的启动检查报告，编译产物不能单独证明成功。

## 隔离与未覆盖范围

候选与可见预览复用原无preload/无Node/无工作台桥接的sandbox renderer、独立非持久session、固定自定义协议资源、CSP、权限/导航/下载拦截、DNS和无DIRECT回退的代理策略。活性求值只执行受信固定常量。退出、取消、替换和崩溃会清理候选、窗口及本地代理。

这不是完整系统沙箱或业务验收。没有自动复现全部点击/输入路径、功能等价检查、任意业务后端、数据库迁移、源码导出或Windows/干净系统验证。本轮只使用合成模型响应，未新增真实供应商请求。具体真实执行与失败修正见[验证报告](evidence/2026-10-04/S3-02/runtime-feedback/result.md)。


## 0.11.0应用窗口扩展

运行记录新增application模式，首次持久应用记录原子升级runtime-reports schema 2，仍读取旧schema 1；使用过该功能的项目应继续使用0.11.0或更新版。临时预览与持久应用分别维护后续错误通道，互不遮蔽。同产物聚焦不重新加载，新打开持久应用必须匹配当前源码。候选检查只用空临时数据，真正持久窗口使用新会话；实际加载可以提交数据，随后失败不回滚已提交数据。详见[数据协议](PERSISTENT_APP_DATA.md)。
