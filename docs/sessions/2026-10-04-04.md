# 2026-10-04会话04：发布前开发轮数估算

执行者Codex，recovery_ui独立只读评估。用户询问大概还需多少开发轮达到可发布版本。读取当前台账、状态、PRD首版及待确认范围、技术方案、开发阶段出口与此前估算记录；本轮不实施新功能。

## 估算口径

一轮指类似0.9.0/0.10.0/0.11.0的一个实现增量，包含必要测试、问题修复和交接文档，不是一次聊天消息，也不对应固定小时数。发布指既定Mac和Windows本地工作台首版，不包含生成网站公网托管、商业化或新增应用类型。

主代理当前工程判断：还需约12—18轮，适合按约15轮规划。范围包括尚缺功能、真实案例、双平台验证和通常的缺陷收敛；不是统计预测或发布日期承诺。协作代理较乐观估算10—15轮，主代理将完整用量/授权、分析适配和发布返工的余量计入最终区间。各工作包可能合并或拆分，不能由主任务数量、测试数量或版本号换算完成率。

| 剩余工作包 | 粗估轮数 |
| --- | --- |
| 源码导出、用量与项目服务授权收口 | 2 |
| 完整分析、任务编排与差距报告 | 2—3 |
| 业务数据、迭代、迁移与恢复 | 2—3 |
| 真实模型完整案例与业务验收 | 1—2 |
| Mac/Windows安装、升级与干净环境验证 | 3—4 |
| 用户试用、体验/性能修正与发布收尾 | 2—4 |
| 合计 | 12—18 |

图片等博客细节、补充案例及平台最低系统/CPU矩阵沿用现有待审阅基准估算，仍需要在相应实现/验收前冻结；本表不将建议升级为用户确认需求。范围不扩张，且不发生重大架构重做，是该区间成立的前提。

## 不确定性与外部条件

主要变数为真实模型面对完整需求时的成功率、Blueprint完整适配，以及尚未实测的Windows运行链路。若发现架构级问题，可能超过18轮。Windows测试环境、签名/公证条件和真实试用者若不能及时提供，会增加等待时间；等待无法直接折算成开发轮数，也不能通过开发者模拟代替验收。

建议每完成约3个实际开发增量按缺陷与验收证据重估。这是进度管理建议，没有创建自动任务、提醒或后台执行计划。
